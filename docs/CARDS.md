# کاتالوگ کارت‌ها — پیوی مشتری و گروه لاگ

**وضعیت: طرح. هیچ کدی نوشته نشده.** ضمیمه‌ی `docs/MULTI_CUSTOMER_PLAN.md`.
تاریخ: ۲۰۲۶-۰۸-۱۳

برای هر رویداد **دو نسخه** طراحی شده: یکی برای پیوی مشتری، یکی برای گروه لاگ. هر دو
از یک رویداد ساخته می‌شوند و با **کد پیگیری** به هم وصل‌اند.

---

## ۰) سیستم طراحی — قواعدی که همه‌ی کارت‌ها رعایت می‌کنند

۱. **یک رویداد = یک عنوان یکسان + یک کد پیگیری یکسان** در هر دو نسخه. مشتری می‌گوید
   «A3F9C1 خوردم»، مالک همان را در گروه سرچ می‌کند.
۲. **کارت مشتری = «چه شد و چه کنم».** کارت لاگ = همان + **زمینه‌ی مالکیت** + **جزئیات
   فنی**. یعنی کارت لاگ همیشه اَبَرمجموعه‌ی کارت مشتری است.
۳. **مشتری هرگز نمی‌بیند:** پاسخ خام سرور، نام موتور، زمان مراحل، مسیر فایل، نام متد،
   آمار ناوگان، وجود مشتری‌های دیگر.
۴. **مشتری همیشه می‌بیند:** کد پیگیری (تا بتواند به پشتیبانی بدهد) و **کاری که باید
   بکند**.
۵. **شماره همه‌جا ماسک** (`98916***736`) — هم پیوی مشتری، هم گروه لاگ. کامل فقط در
   پنل مالک.
۶. **کارت لاگ همیشه این چهار سطر را دارد:** کد پیگیری · مشتری (نام + آیدی) · شماره ·
   زمان.
۷. **کارت‌های زنده در جا ویرایش می‌شوند**، هرگز پیام جدید نمی‌فرستند. `msg_id` در
   دیتابیس ذخیره می‌شود تا بعد از ری‌استارت ادامه بدهد نه از نو.
۸. **هرگز per-recipient لاگ نمی‌شود.** فقط شروع، پایان، و پایان نوبت هر اکانت.

قالب مشترک:
```
<اموجی> <عنوان>
━━━━━━━━━━━━━━━━
کلید : مقدار
━━━━━━━━━━━━━━━━
<سطر اقدام یا وضعیت>
```

### ۱-۴) لاگین ناموفق ❌

عنوان یکسان، محتوای متفاوت. **علت‌ها:**

| کد داخلی | جمله‌ی مشتری |
|---|---|
| FLOOD | «ایتا محدودیت گذاشته — **۶۰ دقیقه** دیگر امتحان کن» ← عدد واقعی سرور |
| کد اشتباه/منقضی | «کد درست نبود یا منقضی شد. دوباره شروع کن و کد تازه را سریع بفرست» |
| تایم‌اوت ۳۲۰ ثانیه | «کد را به‌موقع نفرستادی، لغو شد» |
| رمز دومرحله‌ای غلط | «رمز دومرحله‌ای درست نبود» |
| `no_hash` / `sendCode` | «ایتا الان کد نداد. کمی بعد امتحان کن» |
| شماره ثبت‌نشده | «این شماره روی ایتا ثبت نیست» |

**گروه لاگ:** همان + کد پیگیری + آیدی + موتور + زمان مراحل.

## ۸) یک تابع، دو خروجی

تمام این جدول با **یک نقطه‌ی خروجی** پیاده شود:

```
emit(event, customer_id)
   ├─ گروه لاگ  : کارت کامل
   └─ پیوی مشتری: نسخه‌ی امن (اگر داشته باشد)
```

اگر پخش باشد، یک روز یک کارت کامل اشتباهاً به مشتری می‌رود. اگر یک‌جا باشد، ممکن
نیست. کد پیگیری هم همان‌جا یک بار ساخته می‌شود تا در دو نسخه **یکی** باشد.
