# بخش ۰ — سبک

قالب واحد همه‌ی کارت‌ها و پنل‌ها:

```
🤖 عنوان
-------------------------------

• کلید: مقدار
• کلید: مقدار

-------------------------------
▪ سطر پایانی
```

قواعد سبک:

۱. **خط جداکننده `-------------------------------`** — همان سبک پنل فعلی مالک.
۲. **سطرها با `•` شروع می‌شوند.** خلاصه و مجموع‌ها با `▪`.
۳. **ستون تراز نکنیم.** `کلید    : مقدار` روی موبایل تلگرام **خراب می‌شود**، چون فونت
   تلگرام monospace نیست و فاصله‌ها جمع نمی‌شوند. پس فقط `• کلید: مقدار`.
۴. **سطرها کوتاه.** تلگرام روی موبایل می‌شکند؛ سطر بلند بد دیده می‌شود.
۵. **یک خط خالی** بالا و پایین بدنه، برای نفس‌کشیدن. بیشتر از این نه.
۶. **حداکثر دو خط جداکننده** در هر کارت. بیشتر شبیه جدول سایت می‌شود.
۷. **سطر پایانیِ کارت لاگ همیشه:** `▪ 🔖 <کد پیگیری>  ·  🕒 <ساعت>`
۸. **سطر پایانیِ کارت مشتری:** یا خلاصه، یا کاری که باید بکند.
۹. چیزهای مرتبط با دو فاصله و `·` در **یک سطر** بیایند، نه سطرهای جدا.

## ۵-۲) قواعد

۱. **یک رویداد = یک عنوان یکسان + یک کد پیگیری یکسان** در هر دو نسخه.
۲. **کارت لاگ همیشه اَبَرمجموعه‌ی کارت مشتری است.**
۳. **مشتری هرگز نمی‌بیند:** پاسخ خام سرور، نام موتور، زمان مراحل، مسیر فایل، آمار
   ناوگان، وجود مشتری‌های دیگر.
۴. **مشتری همیشه می‌بیند:** کد پیگیری و کاری که باید بکند.
۵. **شماره همه‌جا ماسک** — پیوی مشتری و گروه لاگ. کامل فقط پنل مالک.
۶. **کارت لاگ همیشه دارد:** مشتری (نام + آیدی) · شماره · کد پیگیری · ساعت.
۷. **کارت‌های زنده در جا ویرایش می‌شوند**، با `msg_id` ذخیره‌شده.
۸. **هرگز per-recipient لاگ نمی‌شود.**

## ۵-۳) یک تابع، دو خروجی

```
emit(event, customer_id)
   ├─ گروه لاگ  : کارت کامل
   └─ پیوی مشتری: نسخه‌ی امن (اگر داشته باشد)
```
کد پیگیری همان‌جا **یک بار** ساخته می‌شود تا در دو نسخه یکی باشد.
